# Preparing one local source batch

Product A supplies source/integration task phases, authenticated pending-revision
CAS and host admission. This repository operator command consumes their frozen
V1 `MeshSourceCandidate` / `MeshIntegrationBatchContract` handoff. It prepares
local commits; source completion and batch preparation do not grant publication
or feature acceptance.

1. Admit one integration task through the normal host/H1 path. Create its pinned
   dependency-free placeholder, then use one authenticated pending CAS to install
   `phase=integration` and its source dependencies. Keep the real task revisions,
   candidate pins, test-log hashes, manifest/patch hashes and overlap ordering.
   Source task results must remain `not_mergeable`. Do not revise active writers.
   For an uncommitted source packet, stage its tested source bytes and run
   `node oss/scripts/refine-source-candidate.mjs /private/path/source-plan.json`
   in its already admitted worktree. This plan contains `rootRepo`, `candidate`,
   successful test-log file paths in `logs`, and the later `requiredGates` IDs.
   Both bases must match the current source HEADs. Normal source-only OSS/root
   commits run with zero generation and produce a private verified-candidate
   packet under `refine-source-candidates/<taskId>` in that worktree's Git dir.
   Its captured exact patch/manifest/test logs and new SHAs feed the frozen batch
   below. A started seal cannot be replayed after an ambiguous interruption.
2. Freeze a private JSON plan containing `contract`, `rootRepo`, `ossRepo`, a new
   `workspace` path, `resolvedTasks`, `evidence`, `reserveBytes` and
   `peakAdditionalBytes`. `resolvedTasks` is the admitted operator's export of
   completed source tasks, not untrusted MCP/peer authority: each record includes
   taskId/revision/missionId/repoIdentity/integrationTaskId, source phase,
   completed status, not_mergeable branchState and `candidateSha256` of the
   serialized candidate. Evidence maps each task ID to patch/manifest files and
   ordered log files. The command verifies all digests, object pins, gitlinks,
   declared changed paths and explicit overlap order. Keep this plan private.
3. Run `node oss/scripts/refine-source-batch.mjs /private/path/plan.json` from a
   prepared checkout. The first invocation creates separate root/OSS integration
   worktrees and may stop with `prepared_workspace_required`. Provision those
   worktrees through the ordinary separately budgeted dependency/bootstrap
   process, then invoke the same unchanged plan. The command never installs or
   shares another writer's dependencies. It reserves at least 1 GiB beyond the
   explicitly estimated additional peak. The common-repository Git lease is an
   additional serialization fence; it does not replace host admission.
4. Each source history is merged, without rebase, into its corresponding
   integration worktree. Real source conflicts stop with `source_conflict` and
   retain the workspace for review. Only explicit regular generated MCP paths
   are restored from the frozen baseline for deferred generation. The combined
   OSS checkpoint, rather than a sibling gitlink, is staged in the root.
5. Normal hooks validate source markers against the entire staged index and
   private frozen contract. Markers carry hashes/IDs and `releaseReady=false`;
   canonical worktree/task details stay in private Git metadata. Both private
   Refinery and the shared public push guard refuse a source-only tip, including
   legacy requests. Removing its marker requires an actual combined-build and
   successful configured-gate receipt through the normal hook.
6. After all sources are staged, the command automatically invokes
   `npm run bundle:vendor:all` once, then every ordered gate in the frozen
   `.adhdev/refine.json` configuration. It records commands, exits, log hashes,
   stage/build counts and wall time. It first materializes the generated bytes
   in normal source-only local checkpoints, so committed-HEAD vendor gates can
   inspect the actual combined output. Those checkpoints remain unpublishable.
   Final normal hooks validate exact staged
   source/output digests and private command-log proofs. Root/OSS local final
   commits, generated JS/map parity and the exact root gitlink must agree.
7. Request independent combined review and owner approval of the newly prepared
   exact SHAs. Use the ordinary Refinery publication path only after that later
   authorization, with fresh per-node/per-repository pending SHA sets, identities,
   full main..target scanning, CAS and the chained real pre-push hook. The plan's
   approved input pins never authorize its newly generated/merged commits.

The journal lives in the root common Git directory under
`refine-source-batches/<batchId>`. Repeating a settled `batch_ready` preparation
does not publish or regenerate. Changed plans, revisions and checkpoint heads
are rejected. Cancellation before a step persists a stop. A crash/ambiguous
effect records `inFlight` before launching a mutating command and requires
explicit reconciliation under normal admission; there is no automatic takeover,
rebase, retry of possibly completed generation, or publication. Preserve the
workspace, journal and logs when resolving such a stop. Replanning requires a
new audited frozen batch, not deletion/editing of its journal.

Ordinary OSS/root commits also share an automatically produced generation proof:
the first normal hook generates both copies from staged sources, and the
following root hook reuses it only when both complete source indexes, clean
source worktrees, generated bytes and the successful log still match. A changed
gitlink/source/output invalidates reuse. This has no environment skip flag and
does not waive the configured integration gates above or later review.

Native eligible-worker concurrency and live before/after timing remain a separate
post-rollout validation requiring owner deployment/restart authorization. Local
Git fixtures and recorded command timings do not establish that live result.
