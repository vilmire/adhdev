# ADHDev

**コーディングエージェントのコントロールプレーン: すべてのマシンのすべてのエージェントを 1 つの画面で、共有タスクキューは 1 つ、テストを通過した作業だけが `main` に入ります。**

AI コーディングエージェントは、長時間動き続けるバックグラウンドワーカーになりました。ADHDev はそのためのコントロールプレーンです。Web またはモバイルのダッシュボードからエージェントセッションを起動し、見守り、承認し、舵取りできます。Claude Code、Codex、Kimi、Cursor CLI、Antigravity CLI、Grok CLI、OpenCode を、お持ちのすべてのマシンにわたって並べて扱えます。そして、完了した作業を `main` にマージする無人のパイプラインに収束を任せられます。

**衝突のない並列エージェント。** すべてのタスクは専用の git worktree で実行されます。Refinery は完了した作業をゲートにかけ、検証し、main にリベースし、main が動いていない場合にのみマージします。マージ日の二日酔いはありません。

ウェブサイト: **[adhf.dev](https://adhf.dev)** · ドキュメント: **[docs.adhf.dev](https://docs.adhf.dev)**

**1 コマンドで試す:** `npx @adhdev/daemon-standalone` を実行し、http://localhost:3847 を開きます。

**ループ:** チャットでタスクを説明 → コーディネーターが登録し、タグ付けし、キューに入れる → 空いているマシンが新しいワークツリーに取り込む → リポジトリ自身のゲートが判定 → `main` にリベースされ、`main` が動いていない場合にのみマージ、ワークツリーは消える。スマートフォンが鳴るのは、承認が必要なときだけです。

ADHDev はこの方法で作られています。ADHDev を開発している非公開のモノレポ（このエンジンはそこからサブモジュールとして公開されています）では、`main` のコミットのおよそ 6 件に 1 件が `Auto-merge branch '…' via Refinery` コミットです。エージェントが完了し、リポジトリ自身のゲートが承認し、人が `git merge` を実行することなく Refinery が反映した作業です。その履歴は上流のモノレポにあるため、この公開ミラー自体のログにはそれらのマージコミットは現れません。

## ADHDev の特長

### 🕸️ Repo Mesh — 真のマルチマシン並列処理
（セルフホストでは、mesh は互いに直接届くマシン（同じネットワークまたは Tailscale）にまたがれます。mesh 画面でアドレスとワンタイムコードを使ってペアリングし、アカウントは不要です。クラウド版は自分のネットワークの外まで到達範囲を広げます。）依存関係付きでタスクをキューに入れると、コーディネーターが空き容量のあるノード（ノートパソコン、デスクトップ、ビルド用マシン）に振り分けます。これは P2P mesh 上の本物のマルチマシンオーケストレーションであり、1 台のホストへの SSH では**ありません**。各タスクは専用のワークツリーで実行されるため、エージェント同士が干渉することはありません。mesh と Refinery のエンジンはこのリポジトリに含まれ、マシン間の直接ペアリングも含まれます。クラウド版は同じ mesh を P2P でインターネット越しに運びます。

mesh は 1 つの git リポジトリに紐づき、本来は手作業で調整することになる要素を引き受けます。

| | |
| --- | --- |
| **タスクキュー** | プル型。`pending → assigned → completed/failed`。`depends_on` による順序付けとリトライに対応。空いているノードが自分で作業を取りに行くため、同期がずれるプッシュ型スケジューラはありません。 |
| **ミッション** | 多数のタスクをまとめる目標。再起動したコーディネーターは、すべてを再キューイングせず、前回の続きから再開します。 |
| **ワークツリーノード** | 並列タスクごとの独立したブランチのチェックアウト。作業がディスパッチされる前に、自動でブートストラップ（インストール、ネイティブの再ビルド、gitignore 対象のビルド成果物）されます。 |
| **追記専用の台帳** | すべてのディスパッチ、完了、失敗、停滞、チェックポイントを、mesh のローカル SQLite ストアに追記専用レコードとして記録します。「実際に何が起きたか」を後から答えられる監査証跡です。 |
| **運用ノート** | 実行時に記録された教訓（プロバイダーの癖、復旧手順など）は、以後のすべてのコーディネーターのプロンプトに注入されるため、知識は学んだセッションより長く残ります。 |
| **ライブ状態プロンプト** | コーディネーターのシステムプロンプトは静的なテキストではありません。起動時には mesh のライブ状態（ノードの健全性、アクティブなミッション、最近の失敗、蓄積されたノート）をレンダリングしたものになり、実行中はポーリングの代わりにイベントがそのセッションに注入されます。 |
| **難易度 + クォータのルーティング** | タスクに easy / medium / difficult のタグを付けると、その難易度に対応するノードのスロット（プロバイダー、モデル、思考レベル、並列数の上限）が引き受けます。日常的な作業は安価なモデルで動き、難しいタスクだけが高価なモデルを使います。各マシンは、すべての CLI サブスクリプションの残り 5 時間ウィンドウと週間ウィンドウも読み取ります。ほぼ使い切ったプランはスキップされ（タスクは待機するか、そのノードの次のプロバイダーに回ります）、残りのうち、次のリセットで使われないまま失効するクォータから先に消費されます。何かを実行する前に、難易度ごとのルーティング予測をダッシュボードで確認できます。 |
| **タスクチェーン** | `depends_on` でタスクを連鎖させます。依存するタスクは先行タスクの完了を待ち、その完了サマリーを「Upstream results」の付録として受け取ります。失敗またはキャンセルされた先行タスクは、後続のチェーンを保留し（mesh のポリシーによってはキャンセルし）、コーディネーターに通知します。`mesh_enqueue_batch` は、確認済みの複数タスクを 1 回のアトミックな呼び出しでキューに入れます。 |

### 🚢 Refinery — `main` への無人の反映
並列処理は、作業が実際にマージされて初めて意味を持ちます。Refinery は、リポジトリごとの検証ゲート、パッチ等価性チェック、サブモジュール対応のリベースとマージ（main が動いていない場合のみ）、ワークツリーの自動クリーンアップによって、完了したタスクを無人で収束させます。エージェントが終わらせ、Refinery が反映します。上の mesh ボードはパイプラインをライブで表示します。キューを進むタスク、収束の進行中の refine ジョブ、そしてアクティビティフィードにあるすべてのディスパッチ、完了、停滞です。

### 🧩 サブモジュール対応の収束 — 実際のモノレポで動く
並列ワークツリーと無人マージは、git サブモジュールが関わった途端に脆くなります。ADHDev はこのケースに正面から取り組んでいます。このプロジェクト自体がサブモジュール構成のモノレポ（ルートリポジトリに、AGPL のエンジンとプロバイダーカタログがサブモジュールとして加わる構成）であり、mesh と Refinery を毎日自分たちで使っています。Refinery は収束中、サブモジュールを第一級の対象として扱います。

- **到達可能性ゲート** — ルートのブランチが `main` に反映される前に、参照されているサブモジュールのコミットがサブモジュールの `origin/main` から到達可能であることを検証します。到達できない場合、それらのコミットが公開されるまでタスクはブロックとして保留されます。
- **パッチ等価性の検出** — サブモジュールのコミットがリベースまたはスカッシュされて SHA が変わっても、Refinery は*内容*がすでに反映済みかどうかを判定するため、二重マージや誤った乖離の指摘をしません。
- **アトミックなポインター更新** — サブモジュールのポインター更新はルートの変更と一緒に収束するため、無人のマージでルートが壊れた、あるいは宙に浮いたサブモジュールのコミットを指したままになることはありません。

### ⚡ 設計から非同期 — 話しかける先は 1 か所
話しかける先は 1 か所です。コーディネーターがすべてのワーカーとマシンを非同期にオーケストレーションし、待つのはコーディネーターで、あなたではありません。セッションの付きっきりの監視は不要です。各エージェントのウィンドウの前で完了を見張る代わりに、すべてのワーカーを並列に動かす 1 つのコーディネーターに作業を任せ、完了、承認、ステータスのイベントが実際に届いたときだけ反応します。ポーリングも、ブロックする待機もありません。あなたにとっては 1 つの会話で、その下はノンブロッキングのイベントループです。

### 🌐 すべてのセッションを見て、舵を取る
エージェントはローカルで動き、あなたはどのブラウザからでも見守り、操作します。ダッシュボードは実際の操作画面です。アクティブなセッションの確認、チャットとターミナルの状態の閲覧、作業の承認や中断、適切な履歴の再表示、次の指示の送信を、ブラウザまたはスマートフォンから行えます。ターミナルの付きっきりの監視は不要です。承認のプッシュにはコマンドの冒頭部分が含まれます。`rm -rf build/` の承認と `git push --force` の承認では、反応に使うべき時間が違うからです。プッシュが届く → タップする → 1 タップで承認します（スマートフォンへのプッシュはクラウド版に含まれます）。

セッションは、ワークスペース内の Markdown、画像、diff、JSON、テキストなどのファイルを**アーティファクト**としてチャットに載せることもできます。インラインでプレビューされ、必要に応じて開く、コピーする、ダウンロードすることができます。ファイルが登録済みのワークスペースの外に出ることはありません。

### 🛡️ 範囲を絞った承認
- **自動承認は 1 回限りの選択肢だけを押します。** 自動承認がオンのとき、デーモンはワーカーの権限プロンプトに単一の「yes」で答えます。「always」「今後は確認しない」、セッション全体やプロジェクト全体への許可は決して選びません。
- **エージェント自身のボタンを、受信箱に。** 保留中のリクエストには、プロバイダー本来の選択肢が範囲の狭いものから順に表示され、恒久的な許可は最後に、そうとわかるよう示されます。
- **委任されたワーカーは、まずコーディネーターに尋ねます。** ワーカーの権限リクエストはコーディネーターに送られ、1 分経ってもまだ未回答の場合にのみ、あなたにプッシュが届きます。
- **有効なプロンプトだけが対象です。** エージェントが単に出力した、引用した、またはスクロールで流れ去った承認テキストが、本物のプロンプトと見なされることはありません。また、その後に変わったリクエストに対する選択は、応答されずに拒否されます。

### 🧑‍💼 すべてのプロジェクトのための 1 つのアシスタントチャット
ダッシュボードのヘッダーからアシスタントを起動し、動かす CLI を選びます。どのプロジェクトでも、やりたいことを伝えれば、アシスタントは必要に応じてそのプロジェクトのコーディネーターを起動し、あなたの言葉を伝え、結果を同じチャットに、あなたが書いている言語で戻します。環境や好みについての短いメモを保持し（サイズ制限があり、プロジェクトの出力に従う書き込みには承認が必要）、各プロジェクトのレポートと通知をあなたに中継し、1 日 1 回（デフォルトではローカル時間の 09:00）、何が完了し、何がブロックされ、何があなたの対応を待っているかをまとめ、3 日間動きのないミッションを知らせます。判断が必要なときは、タップできるボタンとしていくつかの選択肢を提示します。権限プロンプトに対してアシスタントが返す答えや、アシスタントが提案する設定変更は、そのパネルであなたが選んだときにだけ送信されます。どのアシスタント CLI でも動作し、直近のいくつかのリクエストを再起動後も記憶します。さらに、もう一方のマシンで許可した後は、ローカルにチェックアウトしなくても、あなたの別のマシン上にあるプロジェクト（ペアリング済みのセルフホスト、またはクラウド版）を追跡できます。

### 🔺 マルチパースペクティブレビュー
バグの RCA、設計レビュー、監査など、重要な読み取り専用の調査では、コーディネーターにセカンドオピニオンを依頼できます。同じ質問を異なるプロバイダーの 2〜3 人のワーカーに送り、そのレポートを待って、どこで意見が一致し、どこで食い違い、どの主張が 1 人のワーカーだけのものだったかを整理して示します。意見が高い割合で一致していても、正しいとは限りません。同じモデルが同じコンテキストで同じ間違いを繰り返すからです。したがって、読む価値があるのは食い違いの部分です。

### 🔐 P2P トランスポート（信頼のためであり、有料化のためではありません）
チャット、コマンド、スクリーンショット、リモート入力は、暗号化された WebRTC データチャネルを通じて、ダッシュボードとデーモンの間を直接流れます。サーバーが扱うのはサインイン、シグナリング、軽量なメタデータで、意図的な例外が 1 つあります。クラウド版では、プッシュ通知を作るために承認プロンプト（コマンドとボタンのラベル）を受け取り、プッシュにはその最大 80 文字が表示されます。チャット、ターミナル出力、あなたのコードが他人のサーバーに置かれることはありません。これは設計上の信頼の性質であり、アップセルではありません。

ネットワークの都合でダッシュボードの接続が TURN リレー経由になる場合、ADHDev はバックグラウンドで直接経路を探し続け、新しい経路が検証されてダッシュボードがそちらに移った後にだけ切り替えるため、切り替えでセッションが切れることはありません。

### 📁 自分のマシン間でプロジェクトを移す（クラウド版）
プロジェクトフォルダーを、自分のマシンから別のマシンへ、専用の直接接続で送ります。ファイルのバイトがクラウドサーバーやリレーを通ることはありません。両方のマシンが同じファイル一覧を確認し、シークレット（`.env*`、鍵、クラウドの認証情報、シェル履歴など）は常に除外されます。ファイルは、すべてのバイトが検証された後にのみ、登録済みプロジェクトの下の新しいフォルダーに配置され、既存のものが上書きされることはありません。

### 🧪 ワーカーにブラウザを操作させる
ワーカーは、Playwright MCP ドライバーを通じてローカルのブラウザを操作し、作ったばかりの UI を確認できます。ドライバーは有効化の前に承認が必要で（信頼できる低リスクのパッケージは自動で承認できます）、すべての呼び出しはワーカー自身の認証情報に照らして確認されます。

## 他との比較

- **Claude Code Remote Control、Codex Remote:** 1 つのベンダーのセッションをスマートフォンから操作するには優れています。ADHDev が加えるのは、複数のベンダーとマシンが共有するキュー、それらの間でのクォータ対応ルーティング、そしてテストゲート付きのマージです。1 台のマシンで 1 つの CLI を使うなら、組み込みのリモート機能で十分かもしれません。
- **Paseo、Happy:** コーディングエージェント向けのオープンソースのリモートコントロールとモバイルアプリです。ADHDev が注力するのはプロンプトの後の作業です。空いているマシンがタスクをプルし、それぞれが専用のワークツリーで動き、テストを通過した作業だけが `main` に入ります。
- **Conductor、Superset、Vibe Kanban:** ワークツリーでの並列エージェントで、最後はあなたがレビューしてマージする diff や PR になります。ADHDev は、Mac、Windows、Linux のマシンがプルする 1 つのキューを動かし、ゲートを通過すれば代わりにマージします。

## 仕組み

ADHDev はあなたのエージェントを置き換えたり、独自に起動したりしません。**マシンにすでにインストールされているエージェントに接続**して、操作画面を与えます。

```
   │  · providers  │────────────────────▶│ Cursor, VS Code,     │
   │  · sessions   │                     │ Antigravity, …       │
   │  · mesh/queue │                     └──────────────────────┘
   │  · Refinery   │
   └───────────────┘
         │
         └── git worktrees ── one isolated checkout per parallel task
```

- **連携はデーモンが担います。** プロバイダーには 3 つのカテゴリーがあります。`cli`（PTY）、`ide`（Chrome DevTools Protocol）、`extension`（CDP webview）です。
- **長寿命のランタイムは別プロセスです。** `adhdev-sessiond` が PTY を保持するため、デーモンの再起動やアップグレードがあっても CLI セッションは生き残ります。
- **セルフホスト版はデーモンと直接通信します。** `localhost:3847` 上の HTTP + WebSocket を使います。クラウド版では、同じデータがブラウザとデーモンの間の WebRTC データチャネルで流れ、サーバーはシグナリングだけを担当します。

### タスクをキューに入れると何が起きるか

```
mesh_enqueue_task  →  SQLite queue (pending)
                   →  an idle node claims it (assigned)
                   →  worker agent runs in its own git worktree
                   →  completed / failed  →  append-only ledger
                   →  Refinery: repo's own gates → patch equivalence → rebase → merge (main unchanged) → cleanup
```

他のすべてを形作る 4 つの性質:

1. **コーディネーターは振り分けるだけで、実装はしません。** コーディネーター自身がコードを読んだり編集したりせず、mesh ツールをオーケストレーションするため、コンテキストが小さく保たれ、その担当はデーモンの再起動をまたいで維持されます。
2. **ポーリングは一切ありません。** ワーカーの完了、承認、refine のレポートは、発生した時点でコーディネーターのセッションに直接届けられます。画面のスクレイピングではなく、構造化された `report_completion` 呼び出しによります。待つのはイベントであり、ループで状況を尋ねることはありません。
3. **証明は git であり、エージェントの言葉ではありません。** 「完了」は、ワーカーが成功したと主張することではなく、実際の git の状態とコミットのチェックポイントで検証されます。
4. **曖昧さはパイプラインを止めます。** Refinery は決して force-push しません。判断できないものは、マージされず、人の判断のために保留されます。

> 詳細: [Repo Mesh 開発者ガイド](docs/repo-mesh/DEVELOPER.md) · [session-host](docs/self-hosted/session-host.md)

## インストール

**要件:** Node.js 22 LTS（ワンライナーのインストーラーは 22 以上を必要とし、なければインストールします。Windows では 22.x を使用してください。下の注記を参照）、git、そしてインストールと認証がすでに済んでいるコーディングエージェントが少なくとも 1 つ。ADHDev は、すでにお使いの CLI を操作します。

**推奨 — `adhdev` CLI:**

```bash
npm install -g adhdev
adhdev standalone
```

**`http://localhost:3847`** を開きます。

**standalone パッケージで直接セルフホストする:**

```bash
npm install -g @adhdev/daemon-standalone
adhdev-standalone
```

すべてがあなたのマシン上で、ダッシュボード内蔵のローカルデーモンとして動作します。standalone の経路ではクラウドアカウントは不要です。どちらのパッケージも `adhdev` コマンドをインストールするため、どちらか一方だけをインストールしてください。

**クラウド版（複数マシン、プッシュ通知）:**

```bash
curl -fsSL https://adhf.dev/install | sh      # macOS / Linux
irm https://adhf.dev/install.ps1 | iex         # Windows (PowerShell)
brew tap vilmire/adhdev && brew install adhdev # macOS / Linux の Homebrew（Node.js 同梱）
adhdev setup                                   # サインイン後、https://adhf.dev を開く
```

便利なフラグ:

```bash
adhdev standalone --host 0.0.0.0  # 同じ LAN の他のデバイスからのアクセスを許可
adhdev standalone --port 8080     # ポートを指定
adhdev standalone --token mysecret # スクリプト・運用者アクセス用のトークン認証
adhdev standalone --no-open       # ブラウザを自動で開かない
adhdev standalone --dev           # プロバイダーのデバッグ・テスト用にローカルの DevServer エンドポイント (:19280) を有効化
adhdev-standalone --public <dir>  # (standalone パッケージ) カスタム Web ダッシュボードのビルドを配信
```

standalone はデフォルトで localhost のみです。LAN からアクセスするために `0.0.0.0` にバインドした場合、トークン認証もダッシュボードのパスワードも設定されていなければ、ダッシュボードが警告を表示します。

> **Windows に関する注記:** Windows + Node.js 24 以降は、現在、通常の起動・インストール経路ではブロックされています。Node.js 22.x か、PowerShell インストーラーを使用してください: `irm https://adhf.dev/install.ps1 | iex`（[ドキュメント](https://docs.adhf.dev)）。

セルフホストの正規ドキュメント:

- [セルフホストのセットアップ](docs/self-hosted/setup.md)
- [セルフホストの設定](docs/self-hosted/configuration.md)
- [セルフホストのローカル API](docs/self-hosted/local-api.md)

### 最初の 5 分

1. **デーモンを起動する** — `adhdev standalone` を実行し、`http://localhost:3847` を開きます。ダッシュボードが、このマシンにインストールされているエージェントを検出します。
2. **セッションを起動する。** プロバイダー（たとえば Claude Code）と作業ディレクトリを選んで開始します。チャットで操作することも、生のターミナルとして見守ることもできる、本物のエージェントセッションが手に入ります。2 つは切り替えられます。
3. **作業を送って、その場を離れる。** タスクを入力します。エージェントが権限プロンプトに行き当たると、見ていないターミナルをブロックする代わりに、ダッシュボードのアクティビティ受信箱に承認として表示されます。（こうした承認をスマートフォンへプッシュする機能はクラウド版の機能です。）
4. **説明だけでは足りないときは、スクリーンショットをチャットに貼り付ける**と、エージェントのコンテキストに直接入ります。
5. **1 台のマシンで mesh を試す。** `/mesh` を開き、リポジトリに紐づく mesh を作成して、ワークツリーノードをクローンします。そこにタスクをキューに入れ、台帳を見守ります。ディスパッチ → 完了 → Refinery → リベースして `main` にマージ。これはすべてセルフホストで動作します。同じネットワークまたは Tailscale 上の 2 台目のマシンを追加するには、mesh 画面でそのアドレスとワンタイムコードを使ってペアリングします。自分のネットワークの外にあるマシンに到達する場合にだけ、クラウド版が必要です。

行き詰まったら、[セルフホストのセットアップガイド](docs/self-hosted/setup.md)で、ポート、LAN への公開、プロバイダー検出の問題を扱っています。

## 対応エージェント

ADHDev は、3 つのプロバイダーカテゴリー（`ide`（CDP）、`extension`（CDP webview）、`cli`（PTY））を通じてコーディングエージェントと通信します。

**CLI エージェント**（PTY で駆動され、ダッシュボードから起動・制御されます）:

| エージェント | プロバイダー |
| --- | --- |
| Claude Code | `cli/claude-cli` |
| Codex CLI | `cli/codex-cli` |
| Cursor Agent | `cli/cursor-cli` |
| Google Antigravity CLI | `cli/antigravity-cli` |
| Grok CLI | `cli/grok-cli` |
| Kimi Code | `cli/kimi` |
| Opencode | `cli/opencode` |

**IDE**（Chrome DevTools Protocol 経由）: Cursor、Google Antigravity、VS Code、VSCodium、Kiro、Windsurf、Trae、PearAI。

**IDE 拡張機能**（CDP webview）: Claude Code (VS Code)、Codex、Cline、Roo Code。

> **組み込み ≠ 検証済み。** ADHDev は幅広い一覧を同梱していますが、カタログに載っていることは連携が存在することを意味するだけで、すべてがエンドツーエンドで検証済みという意味ではありません。サポートレベルはさまざまです。最新のポリシーはこちらをご覧ください。
>
> - [対応プロバイダー](https://docs.adhf.dev/reference/supported-providers)
> - [対応 IDE](https://docs.adhf.dev/reference/supported-ides)
> - [互換性と注意事項](https://docs.adhf.dev/guide/compatibility)

ADHDev はエージェントの API キーを管理**しません**。各ツールが自分で認証を扱います。ADHDev はインストール状況を検出し、エラーを表示します。

### 独自のエージェントを追加する

プロバイダーはデータであり、フォークが必要なコードではありません。プロバイダーは、バージョン付きのマニフェスト（`provider.v1.json`）と、ツールの検出方法、起動方法、出力をチャットのターンに解析する方法、承認プロンプトの認識方法を記述するスクリプトで構成されます。`~/.adhdev/providers/` に置けばダッシュボードが取り込み、同名の組み込みよりあなたの上書きが優先されます。そのため、壊れたパーサーをリリースを待たずにローカルで修正できます。

- 検証のティアは明示されています: **Verified / Partial / Unverified**。「組み込み」は連携が存在することだけを意味します。
- ガイド: [対応プロバイダー](https://docs.adhf.dev/reference/supported-providers) · [カスタムプロバイダーガイド](https://docs.adhf.dev/guide/custom-providers)

カタログにないエージェントを動かせたなら、それが最も役に立つ貢献です。[vilmire/adhdev-providers](https://github.com/vilmire/adhdev-providers) に対して提出してください。ここでのコアへのプルリクエストには、CLA への署名が必要です（ボットが案内します）。

## このリポジトリの内容

これはオープンソースのセルフホスト版（AGPL-3.0）です。ホスト型クラウドの運用部分はこのリポジトリに含まれません。セルフホスト版は 3 つのローカルレイヤーで構成されます。

1. `daemon-standalone` はローカルの HTTP/WebSocket サーバーを公開し、Web UI を配信します。
2. `daemon-core` は IDE、CLI、拡張機能の連携を管理します。
3. `session-host-daemon`（`adhdev-sessiond`）は長寿命の PTY ランタイムを保持し、デーモンの再起動後も CLI セッションが生き残るようにします。

| パス | 目的 |
| --- | --- |
| `packages/daemon-core` | 共有エンジン: プロバイダー、CDP、コマンドルーティング、セッション/ランタイムの状態 |
| `packages/daemon-standalone` | ローカルの HTTP/WS サーバーと同梱の standalone UI |
| `packages/web-core` | 共有の React ページ、コンポーネント、フック、トランスポートの抽象化 |
| `packages/web-standalone` | standalone ダッシュボードアプリ |
| `packages/session-host-core` | session-host のプロトコル、クライアント、レジストリ、リングバッファ、ラベル |
| `packages/session-host-daemon` | 長寿命の PTY ランタイムを保持するプロセス |
| `packages/terminal-mux-*` | ローカルのターミナル mux スタック |
| `packages/terminal-render-web` | ブラウザ側のターミナル描画サポート |
| `packages/ghostty-vt-node` | ランタイム/mux レイヤーが使う Ghostty VT バインディング |

### standalone の API

- `GET /api/v1/status` — sessions[] 配列が信頼できる情報源です
- `POST /api/v1/command`
- `GET /api/v1/runtime/:sessionId/snapshot`
- `GET /api/v1/runtime/:sessionId/events`
- `GET /api/v1/mux/:workspace/state`
- `POST /api/v1/mux/:workspace/control`
- `ws://localhost:3847/ws`

リファレンス: [セルフホスト API ドキュメント](docs/self-hosted/local-api.md)

## OSS とクラウドの違い

エンジンはオープンソースです。クラウドが加えるのは**到達範囲のレイヤー**です。アカウント、直接届くマシンだけでなくどこにあるマシンでも、インターネット越しのリモートアクセス、そしてプッシュです。

| | OSS（セルフホスト） | クラウド（[adhf.dev](https://adhf.dev)） |
| --- | :--: | :--: |
| ダッシュボード | `localhost:3847` | `adhf.dev`、任意のブラウザまたはスマートフォン |
| アカウント必須 | ❌ 認証なし | OAuth（GitHub / Google） |
| マシン数 | 実行しているマシン + 直接ペアリングしたマシン（同じネットワーク / Tailscale） | プランにより 1 / 2 / 5、どこからでも |
| 到達範囲 | localhost、または `--host` を付けた LAN / Tailscale | **どこからでも**（P2P WebRTC + 制限の厳しいネットワーク向けの TURN） |
| すべてのプロバイダー（CLI / IDE / 拡張機能） | ✅ | ✅ |
| Repo Mesh、Refinery、ワークツリーノード | ✅ **完全にローカルで動作** | ✅ |
| **マシンをまたぐ** mesh | ✅ 届くネットワーク上での直接ペアリング（アドレス + ワンタイムコード） | ✅ どこからでも（P2P + TURN） |
| アシスタント（中継、日次サマリー、ワンタップ回答） | ✅ | ✅ |
| 別のマシン上のプロジェクトを追跡するアシスタント | ✅ ペアリング済みのマシン | ✅ |
| マシン間のプロジェクトファイル転送 | ❌ | ✅ |
| プッシュ通知（承認 / 完了 / エラー） | ❌ | ✅ |
| ホスト型 REST API + API キー | ❌（ローカル API のみ） | ✅ |
| 価格 | 無料、クォータなし | Free / Pro / Ultra |

マシンが 1 つのネットワーク（または 1 つの Tailscale）上にあるなら、セルフホスト版でプッシュ通知、ホスト型 API、プロジェクトのファイル転送を除くすべてが使え、クォータもありません。クラウドが意味を持つのは、マシンがそのネットワークの外にあるとき、または家の外からエージェントに到達したいときです。
